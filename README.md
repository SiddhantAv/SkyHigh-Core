# SkyHigh Core

**SkyHigh Core** is a **Digital Check-In System API**: a FastAPI backend for **concurrency-safe seat holds and confirmations**, **Redis-backed seat maps**, **baggage-aware check-in**, and **simulated extra-baggage payment**. It uses **PostgreSQL** as the system of record and **Redis** for caching, rate limits, and optional seat locks.

## Prerequisites

- **Python 3.11+** (see `pyproject.toml`)
- **PostgreSQL** and **Redis** for a full local or Docker setup
- **Docker & Docker Compose** (optional, recommended for Postgres + Redis + API + worker)

## Quick start (local, without Docker)

### 1. Virtual environment and dependencies

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

(On Unix: `source .venv/bin/activate`.)

### 2. Environment variables

Create a `.env` file in the project root with at least `DATABASE_URL` and `REDIS_URL`. If the repository includes `.env.example`, copy it first:

```powershell
if (Test-Path .env.example) { copy .env.example .env }
```

At minimum set:

- `DATABASE_URL` — e.g. `postgresql+psycopg://user:pass@localhost:5432/skyhigh`
- `REDIS_URL` — e.g. `redis://localhost:6379/0`

See **Configuration** below for the full list.

### 3. Database setup (Alembic)

Migrations are driven by **`DATABASE_URL`** (via `skyhigh.config.get_settings()` in `alembic/env.py`).

From the **repository root**, with the venv active and `.env` loaded (or variables exported):

```powershell
python -m alembic upgrade head
```

To create a new migration after model changes:

```powershell
python -m alembic revision --autogenerate -m "describe change"
python -m alembic upgrade head
```

Always review autogenerated revisions before applying in production.

**Note:** The initial revision in this repo may be empty until you autogenerate from the ORM models; ensure `alembic/env.py` imports `skyhigh.db.models` so all tables are on `Base.metadata`.

### 4. Run the API

The package lives under `src/`. Either set `PYTHONPATH` or use Uvicorn’s `--app-dir`:

```powershell
uvicorn skyhigh.main:app --reload --app-dir src --host 0.0.0.0 --port 8000
```

If you installed editable (`pip install -e .`), you can often run:

```powershell
uvicorn skyhigh.main:app --reload --host 0.0.0.0 --port 8000
```

**URLs**

- API docs: [http://localhost:8000/docs](http://localhost:8000/docs)
- Liveness: [http://localhost:8000/api/v1/health](http://localhost:8000/api/v1/health)
- Readiness (DB + Redis): [http://localhost:8000/api/v1/health/ready](http://localhost:8000/api/v1/health/ready)

### 5. Run background workers

#### Seat expiry worker (recommended in production)

Releases stale **HELD** seats in batches (PostgreSQL `SKIP LOCKED`) and invalidates seat-map cache entries. Uses the **same** `DATABASE_URL` and `REDIS_URL` as the API.

```powershell
$env:PYTHONPATH = "src"
python -m skyhigh.workers.expiry_loop
```

Or with `pip install -e .` and correct working directory / path:

```powershell
python -m skyhigh.workers.expiry_loop
```

Configurable: `SEAT_EXPIRY_BATCH_SIZE`, `SEAT_EXPIRY_WORKER_INTERVAL_SECONDS` (see table below).

#### Idempotency key cleanup

There is **no** long-running CLI module in Compose for this, but the function **`run_idempotency_cleanup(session, settings)`** in `skyhigh.workers.idempotency_cleanup_worker` deletes `idempotency_keys` older than `IDEMPOTENCY_TTL_HOURS`. Schedule it via cron, a job runner, or a small script that opens a DB session and calls it.

## Docker Compose

**Canonical file:** `docker-compose.yml` in the **repository root** (starts PostgreSQL, Redis, API, and the seat expiry worker).

```powershell
docker compose up --build
```

Apply migrations after the stack is healthy:

```powershell
docker compose exec api python -m alembic upgrade head
```

Legacy path (includes the root file): `docker compose -f docker/docker-compose.yml up --build` from the `docker/` directory.

Services:

| Service | Role |
|---------|------|
| `postgres` | PostgreSQL 16 |
| `redis` | Redis 7 |
| `api` | FastAPI on port **8000** |
| `expiry-worker` | Runs `python -m skyhigh.workers.expiry_loop` |

**First-time schema** (after containers are up):

```powershell
docker compose exec api python -m alembic upgrade head
```

## Configuration

| Variable | Description |
|----------|-------------|
| `DATABASE_URL` | SQLAlchemy URL (e.g. `postgresql+psycopg://...`) |
| `REDIS_URL` | Redis URL for cache / locks / rate limits |
| `HOLD_DURATION_SECONDS` | Seat hold TTL (default `120`) |
| `USE_REDIS_SEAT_LOCK` | Optional Redis mutex before DB (`false` by default) |
| `SEAT_MAP_CACHE_TTL_SECONDS` | Redis TTL for seat map keys (default `30`) |
| `IDEMPOTENCY_TTL_HOURS` | Age threshold for idempotency cleanup (default `24`) |
| `SEAT_EXPIRY_BATCH_SIZE` | Rows per expiry batch (`SKIP LOCKED`, default `500`) |
| `SEAT_EXPIRY_WORKER_INTERVAL_SECONDS` | Sleep between expiry batches in `expiry_loop` (default `15`) |
| `MAX_BAGGAGE_KG` | Baggage limit before `WAITING_FOR_PAYMENT` (default `25`) |
| `WEIGHT_SERVICE_URL` | Optional POST URL; body `{"passenger_id","declared_kg"}` → response `{"verified_kg"}` |
| `WEIGHT_SERVICE_TIMEOUT_SECONDS` | Timeout for weight service (default `3`) |
| `RATE_LIMIT_ENABLED` | Enable per-IP fixed-window limits (default `true` in `Settings`) |
| `RATE_LIMIT_GET_PER_MINUTE` / `RATE_LIMIT_POST_PER_MINUTE` | IP limits |
| `PASSENGER_HOLD_RATE_LIMIT_ENABLED` | Per-passenger hold burst limit |
| `PASSENGER_HOLD_RATE_PER_MINUTE` | Max new holds per passenger per minute |
| `LOG_LEVEL` | Logging level (e.g. `INFO`) |

## API cheat sheet

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/v1/health` | Liveness |
| `GET` | `/api/v1/health/ready` | Readiness (DB + Redis) |
| `GET` | `/api/v1/flights/{flight_id}/seats` | Seat map (cached) |
| `POST` | `/api/v1/seats/{seat_id}/hold` | Hold seat (idempotent) |
| `POST` | `/api/v1/seats/{seat_id}/confirm` | Confirm seat (idempotent) |
| `POST` | `/api/v1/checkin/start` | Start check-in |
| `POST` | `/api/v1/checkin/complete` | Complete when within baggage limit |
| `POST` | `/api/v1/checkin/payment` | Simulated payment when over limit |

Details: [API-SPECIFICATION.md](API-SPECIFICATION.md).
